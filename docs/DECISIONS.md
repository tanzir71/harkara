# Decisions

- 2026-11-25: Panic wipe is a terminal container boundary. Feature compositions stop before the non-cancellable wipe; network/jobs/media stop, the database closes/deletes before its key, and Activity recreation installs a fresh graph. A retired graph cannot reopen its old database or identity. Filesystem failure leaves the UI locked rather than claiming erasure succeeded.
- 2026-11-25: A generic outbox envelope route carries encrypted pins, check-ins and trip/live control through ordinary rooms; live points also use current LAN/mesh links, never persistent outbox/event storage. Local safety features do not require internet or an enabled public node.
- 2026-11-25: Search uses a rebuildable FTS4 cache inside the encrypted database, covering the latest 5,000 cached Nearby posts and 5,000 non-deleted/unexpired pins, with bounded literal token queries and 50 results. It sends no query to a server and does not pretend to search uncached OSM places.
- 2026-11-25: Map replacement uses a unique validated/synced archive and atomic metadata commit before cleaning the old pack. First-time space checks create the target directory first; failed or cancelled replacements preserve the working map. Location collection rechecks permission on resume and explicit grant, and stops when its screen/module is inactive.
- 2026-11-25: Screen-reader/switch access to PTT gets an explicitly labelled two-second voice burst and immediate Stop action; physical pointer/keyboard input remains held-only, with the existing 15-second hard limit. Lifecycle shutdown releases audio immediately.

- 2026-11-25: Robolectric's Android 35 instrumented SDK is a pinned Gradle-resolved dependency copied to the build directory. Test runtime uses offline resolution, avoiding public Maven requests per test class after CI hit HTTP 429. This changes only test provisioning, not the APK.
- 2026-11-25: Compact SMS DMs reuse the private chat's exact author, timestamp and text for local duplicate matching; encrypted kind-3480 copies map back to the original message's receipts. SMS key-prefix resolution includes explicitly saved chat contacts, not just prior public events. Group/card/media messages cannot silently become SMS.

One line per decision: date, decision, why. Defaults from the handover (§11) are not repeated here.

- 2026-11-25: Seeded from a copy of `nearcast/` without git history; Nearcast's FastAPI `server/`, Vercel files and its product site were dropped. Harkara has no server (BDT 0/month) and gets a new site under `site/`.
- 2026-11-25: Design handover assets live in `design/` (`icons/`, `brand/`, `tokens/`, `copy/`), imported by `tools/import-handover.mjs`, which strips the embedded C2PA provenance blocks so SVGs can be inlined and converted.

- 2026-11-25: The launcher mark's dashed route is expanded into explicit dash segments in the vector drawable, because Android vectors have no `stroke-dasharray`.
- 2026-11-25: App settings use SharedPreferences behind `AppSettings` (a `StateFlow`), not DataStore — one fewer dependency and trivially testable under Robolectric.
- 2026-11-25: Screenshot goldens are Roborazzi images at 360 × 800 dp, mdpi (1:1 with the Figma renders), stored in `app/src/test/screenshots/`; CI verifies them with a 2% change threshold so font rasterising differences between Windows and Linux don't fail the build.
- 2026-11-25: Bangla UI uses Anek Bangla for all UI text styles (Compose has no per-glyph fallback between font families); Latin UI uses Geist with Anek Bangla only for explicit Bangla labels.
- 2026-11-25: R8 minification stays off until M12: BouncyCastle and reflection-heavy libraries are risky to shrink without on-device runs, and the APK is well under the 30 MB budget.
- 2026-11-25: The signing keystore is PKCS12, so the key password equals the store password (PKCS12 has one password); both secrets are still set.
- 2026-11-25: Nearcast's original design spec is kept as `docs/NEARCAST-SPEC.md` for history only; `HARKARA_HANDOVER.md` (outside the repo) and `AGENTS.md` are the rules now.
- 2026-11-25: Landing site templates are JS template-literal modules in `tools/site/` (render, icons, release, text helpers, inline JS sources, `site.css`). `tools/build-site.mjs` writes the pages, `site/assets/site.css` (minified from `tools/site/site.css`), `favicon.svg` and `latest.json` into `site/`; those outputs are git-ignored, so `site/` after a build is exactly the Pages artifact. Committed under `site/`: `config.json`, `.nojekyll`, `assets/tokens.css`, `assets/fonts/`.
- 2026-11-25: Icons are inlined as one per-page SVG sprite (`<symbol>` + `<use>`), holding only the icons that page uses; keeps each page well under the 120 KB budget.
- 2026-11-25: The local test server and Playwright serve `site/` under `/harkara/` (like GitHub Pages), so relative links, the `/` → `en/` redirect and the 404 page's `<base href="/harkara/">` are tested as deployed.
- 2026-11-25: Without a release the install step text drops its size (", {{APK_MB}} MB"), the footer drops "v{{VERSION}}", the SHA-256 box shows "—" with no Copy button, and the armeabi-v7a link opens the Releases page.
- 2026-11-25: `build-site.mjs` treats GitHub API 404 and network errors as "no release yet" (coming-soon page) but fails on other HTTP errors (rate limit, 5xx) so CI never deploys a downgraded page over a real release. If a release has no `latest.json` asset, one is rebuilt from the API asset list and `SHA256SUMS`.
- 2026-11-25: Privacy/verify and 404 pages need a few strings that `landing.json` doesn't have (Verify, certificate label, "published with the first release", not-found line); they live in `tools/site/strings.mjs` (bn + en).
- 2026-11-25: Mock card UIs on the landing keep the small English labels the Figma frames use in both languages ("Task · Pickup", "Khata · IOU", "Handoff code", "by SMS", "Public", "খাবার").
- 2026-11-25: The site's mono font is JetBrains Mono 500 only, Anek Bangla ships 500/600 (Bengali subset) and Geist 400/500/600 (Latin subset cut with fontTools); the Android TTFs for M2 come from the same families (see `site/assets/fonts/README.md`).
- 2026-11-25: secp256k1-kmp is pinned to 0.16.0, the newest release whose `-jni-jvm` runs on JDK 17 (0.17+ needs JDK 21 for the JVM tests). Its arm64 `libsecp256k1-jni.so` is not 16 KB page aligned (lint warning); move to the latest release when CI moves to JDK 21.
- 2026-11-25: XChaCha20-Poly1305 for NIP-49 is HChaCha20 (own code, checked against the draft-irtf-cfrg-xchacha vector) in front of BouncyCastle's RFC 8439 ChaCha20-Poly1305; BouncyCastle 1.78 has no XChaCha. NIP-44 uses BouncyCastle's ChaCha7539Engine and JCA HMAC/SHA-256.
- 2026-11-25: NIP-01 serialization escapes other control characters and lone surrogates as lowercase `\u00xx`, exactly like `JSON.stringify`, so ids agree with nostr-tools for every string.
- 2026-11-25: Harkara app kinds: 3471 task step, 3472 handoff token, 3473 IOU, 3474 IOU signature, 3475 settle, 3476 check-in, 3477 SOS, 3478 SOS update, 23471 live location, 33471 pin. No NIP uses this block. Area chat uses kind 20000 (bitchat's geohash-channel convention).
- 2026-11-25: Key ring = HKDF-SHA256 with an empty salt over the 32-byte seed and labels `harkara/v1/{profile,area/<g5>/<week>,mesh/<date>,session/<id>}`; an invalid scalar retries with `#1`, `#2`… appended to the label. ISO weeks and mesh days turn over on Asia/Dhaka time.
- 2026-11-25: The NIP-49 backup holds the 32-byte root seed in the "private key" field (log_n 16, key-security byte 0x02), not the profile key, so one backup restores every derived key. Backup passwords need at least 8 characters.
- 2026-11-25: The seed file lives at `noBackupFilesDir/identity/root-seed` (inside what panic wipe empties), sealed with an AndroidKeyStore AES-256-GCM key when the provider exists and plain otherwise (Robolectric). If a sealed seed can no longer be opened (keystore reset) the app makes a new identity; restoring a backup brings the old one back.
- 2026-11-25: Keys are made when onboarding completes (an area is chosen), not at install, so "Restore from backup" on the onboarding screen never has to replace a key the user already used.
- 2026-11-25: Peer rate limits count sliding windows over `created_at` (order-independent), only for kind 1 posts; events more than 15 minutes in the future are dropped so the windows cannot be dodged by future-dating.
- 2026-11-25: The mesh dedupe marks an id seen only after the event verifies, so a forged copy with a real id cannot block the real event. Fragments are link-local: every hop reassembles and verifies before relaying.
- 2026-11-25: NIP-13 `meets(event, bits)` requires a committed target in the nonce tag that is at least `bits` (the NIP allows rejecting uncommitted PoW).
- 2026-11-25: The binary codec deflates content only when that is smaller and has an "id omitted" flag for SMS (the decoder recomputes the id); created_at is u32, so events after 2106 cannot be carried in binary.
- 2026-11-25: Nearcast leftovers without an event equivalent yet were removed rather than half-ported: CryptoBox/NearId/AES-GCM DMs, PacketCodec, ReactionCounter, AckStateMachine, ChannelMessage/ChannelFilter, FeedOrdering/PostKind. Votes return as kind 7 (M4), delivery states and channels as events (M5). SosPolicy and RetentionPolicy now work on events.
- 2026-11-25: The backup QR is always drawn with Day ink on Day surface, also in the Night theme, because many scanners cannot read inverted codes.
- 2026-11-25: SQLCipher is pinned to `net.zetetic:sqlcipher-android` 4.10.0: 4.20.0 requires compileSdk 36 and the handover fixes compileSdk 35. The 32-byte database key is random, kept in no-backup storage and erased by panic wipe; JVM tests use a plain in-memory Room database (HarkaraDatabase.inMemory).
- 2026-11-25: The app's relay pool lives in `app/relay` (OkHttp), while the NIP-01 message codec, NIP-11 parsing, backoff, NIP-77 negentropy and the I/O-free LocalRelay live in core/relay so the LAN room and node can reuse them.
- 2026-11-25: Negentropy (NIP-77) is our own Kotlin implementation of protocol v1, written from the published description; it is used for the area-feed catch-up only on relays whose NIP-11 lists 77.
- 2026-11-25: Feed posts carry g tags at precisions 7, 6 and 5; the app subscribes to the area's geohash-5 cell and its eight neighbours and keeps posts within 3 km of the area centre. Peers require NIP-13 ≥ 16 bits; the composer tunes 16–20 bits to about 2 s of mining on the phone.
- 2026-11-25: Relays connect only while an activity is visible or during the 30-minute WorkManager sync (network + battery-not-low constraints), per the battery rule.
- 2026-11-25: The map style builder (core/map/MapStyle) labels with `name:bn` first, falling back to `name`; MapLibre's support for Bangla glyph shaping is listed in HARDWARE.md as unverified.
- 2026-11-25: The emergency handbook (data/handbook, 42 sections, en + bn, ~365 KB) ships inside the APK because the Handbook module is on by default and must work with no network; only further translations would be downloads. Handbook pages use the polite আপনি form (public-safety convention); app UI strings use তুমি.
- 2026-11-25: Task steps are replayed in time order with lifecycle order breaking ties, and steps that aren't valid yet are retried until nothing changes, so a countersign made in the same second as the accept (or from a phone whose clock is behind) still counts.
- 2026-11-25: The 6-digit handoff code is derived from the requester's signed token; the requester commits to scrypt(code, task address + runner, N=2^14) in the countersign step, so the runner's phone checks a typed code offline while trying all million codes stays impractically slow. The token itself never leaves the requester's phone except as the QR (kept in the local_secrets table, never sent by any carrier).
- 2026-11-25: Display names travel as a `name` tag on task offers and accepts (and later IOUs) so they show on phones that never saw a kind-0 profile; names are free text without digits in the UI.
- 2026-11-25: Reputation uses NIP-51-style verified-contact lists (owner → keys verified in person); until verified contacts exist, only tasks the viewer took part in count.
- 2026-11-25: Prayer times use Adhan-Java 1.2.1 (MIT) in core with the Karachi method and Hanafi Asr by default; Qibla uses Adhan's great-circle bearing.
- 2026-11-25: The SOS hold is a custom 3-second press on the connectivity pill with a filling ring (a completed hold doesn't also count as a tap); accessibility services get a long-press action for it.
- 2026-11-25: Incoming SOS cards show within 10 km of the area centre and go silent unless the user turns on "Emergency alerts sound" (off by default); SosPolicy drops repeats inside 30 minutes and muted keys.
- 2026-11-25: Chat receipts are a Harkara app kind, 3479 (`e` per message, `status` delivered|read), gift-wrapped to the author only and never answered. A message is Delivered/Read when every other member has said so; a member's receipt also stops retries of their copies on every carrier.
- 2026-11-25: A NIP-17 room's local id is the first 16 bytes of SHA-256 over the sorted member pubkeys; two members are a DM, three or more a group. Harkara repeats the group `subject` on every message it sends so new phones learn the name.
- 2026-11-25: The sender's chat name travels as an `n` tag (bitchat's nickname convention) inside the rumor; it is the app-wide display name (shared with Tasks and Khata), asked once at the first send if not set yet; no kind 0 is published. Names with a phone-number-like run of 7+ digits are refused on send and hidden on receipt.
- 2026-11-25: The relay pool resumes gift-wrap subscriptions from the last EOSE minus 2 days 1 hour (`resumeSlackSeconds`), because NIP-59 back-dates wraps; the first fetch reaches a week back.
- 2026-11-25: The Wi-Fi room server is our own ~300-line HTTP + RFC 6455 WebSocket server on plain sockets in `core/lan` (no NanoHTTPD): text frames, fragmentation, ping/pong, 128 KB frame cap, 32 clients; it runs in JVM tests unchanged. Discovery is Android NSD `_harkara._tcp` behind `LanDiscovery` (fake in tests), with a random per-session service name.
- 2026-11-25: Every phone in the Wi-Fi room is a server and a client: our wraps are injected into our own room (peers pull them, even later) and published to every peer's room at the same time as they go to the internet outbox. Room servers keep up to 2 000 wraps in memory; the room runs only while the app is in the foreground.
- 2026-11-25: Wi-Fi room messages are kind 20000 with `t` = `wifi` signed by the profile key (so a DM can start from the room) and never go to relays; the area channel is kind 20000 with `g` = geohash-5 signed by the weekly area key. Both expire after 24 h and follow the Chatter rules (≤ 400 characters, no phone numbers).
- 2026-11-25: Voice notes are inline kind 15 rumors, one per 4 KB part (`voice`, `part`, `m`/`file-type`, `duration`, `x`), each wrapped on its own so every event stays under 16 KB; there is no file server. 15 s cap; Opus/OGG 16 kbps on API 29+, AAC/MP4 24 kbps below.
- 2026-11-25: Location-card precision: exact = 5 decimals + 10-digit Plus Code; about 100 m = rounded to 0.001° + 10-digit code of the rounded point; area = geohash-5 centre + 6-digit code. Codes within 0.3° of central Dhaka are shown short with "Dhaka". Open Location Code is our own implementation of the spec, tested on its published vectors.
- 2026-11-25: Chat strings live in `values/strings_chats.xml` and `values-bn/strings_chats.xml` (same keys in both) so parallel milestones don't collide in `strings.xml`.
- 2026-11-25: "Make it a task" is a callback (`onMakeTask(text)`) from the thread; it opens the M7 task composer prefilled with the message (Buy and bring, `items` = the text). `ChatRepository.addSystemNote` and `R.string.thread_task_made` are the hooks for a "You made that message a task" line once the composer reports the posted task back.
- 2026-11-25: Mesh and node modes share an explicit, non-sticky connected-device foreground service. They never start at boot, survive activity backgrounding only after opt-in, and stop on module-off/panic wipe. Lite suppresses mesh. Disaster mode is the explicit shortcut to Event mesh rather than a second hidden radio switch.
- 2026-11-25: BLE uses one advertised GATT service, rotating presence tokens and deterministic single-link dialing; Wi-Fi Aware is an optional second fragmented radio. JVM fake radios and a fake GATT layer verify routing without claiming hardware delivery.
- 2026-11-25: A neighbourhood node extends the Wi-Fi room with public event sync and fixed-path streamed APK/map/handbook downloads. APK sharing alone serves only while its sheet is open. HTTP is needed for local peers; private content remains gift-wrapped end to end.
- 2026-11-25: Outbox off-grid routes are separate from relay acknowledgements: a successful local send means Left this phone, never Reached the network. Atomic SQL updates prevent a late retry or carrier callback from downgrading an acknowledgement or receipt.
- 2026-11-25: M11 LAN file drop and push-to-talk use a dedicated, explicitly started HTTP listener, manual numeric IPv4/port entry and per-offer file consent or explicit PTT pairing/listening; no LocalSend multicast discovery, TLS or authenticated peer identity is implied. Screen stop/disposal closes networking and audio without automatic restart; this keeps optional tools foreground-only and distinct from the chat relay.
- 2026-11-25: M12 `text/tertiary` reuses the existing `text/secondary` colors (Day `#5F6064`, Night `#9A978F`) because tertiary is used for small hints/captions requiring 4.5:1 contrast, not the 3:1 large-text/icon threshold; no new colors were introduced, and Android/CSS outputs remain generated from `design/tokens/tokens.json`.
- 2026-11-25: SMS payload format v1 (`HK1:` + Base64url, `core/wire/SmsCodec`): 8-byte author reference, u32 time, 64-byte signature, compact tag items (hex/UUID/decimal/joined address/back-references), text as Text8 (one byte per Bangla letter) DEFLATEd with a fixed preset dictionary. 32-byte values the receiver already knows become 8-byte references only when the full form doesn't fit two SMS, so gateways and strangers can still verify most SMS.
- 2026-11-25: Short DMs on the SMS rung are a new app kind 3480 (NIP-44 v2 to one `p`, signed by the sender) instead of a NIP-59 gift wrap, which cannot fit two SMS; the SMS carrier sees both numbers anyway. Plaintext is limited to 32 UTF-8 bytes (one NIP-44 padding block).
- 2026-11-25: SMS field limits (`SmsLimits`): check-in place 40 + note 40 characters, SOS note 60, task name 40, TrxID 20, DM 32 bytes; every SMS-eligible kind at those limits fits two GSM-7 parts (`SmsBudgetTest`).
- 2026-11-25: `SEND_SMS` and `RECEIVE_SMS` are declared in the one manifest (Android can only ask for declared permissions) but requested only when the user turns on "Send SMS directly" or "Volunteer SMS gateway"; both SMS receivers ship as disabled components and are enabled/disabled with their switch. No separate no-SMS build flavor for now (one APK set, Obtainium naming); revisit if a store or Play Protect objects.
- 2026-11-25: When Android refuses the SMS permission (e.g. Android 13+ restricted settings for sideloaded APKs) the app shows a guidance screen (App info → ⋮ → Allow restricted settings → Permissions → SMS) instead of detecting the restriction, which has no public API.
- 2026-11-25: The volunteer gateway relays only while relays run (app open or the 30-minute background sync), with no always-on service (battery rule); its 100/day cap counts SMS in and out per Dhaka day, and events are deduplicated by id. The volunteer's own number lives only in their gateway QR (`harkara:gw:`).
- 2026-11-25: Data SMS for "Send SMS directly" use port 7471 and a 3-byte frame header (133-byte frames, any order); every SMS-eligible event fits two frames.
- 2026-11-25: The https deep link (`tanzir71.github.io/harkara/o/`) is declared without `autoVerify`: assetlinks.json would have to be served from the root of tanzir71.github.io, which this project does not control. The o/ page offers an "Open in Harkara" (`harkara:`) button instead.
- 2026-11-25: The web page for non-users bundles @noble/curves + @noble/hashes (MIT) with esbuild (MIT, devDependency) into `site/assets/o.js` (~50 KB) with its own budget (JS 60 KB, CSS 48 KB, page 160 KB); a CSP meta pins WebSockets to `data/default-relays.json` and forbids inline scripts. Compressed `e:` content is inflated with the browser's `DecompressionStream('deflate-raw')` (Chrome 103+, Safari 16.4+, Firefox 113+) rather than bundling an inflater.
- 2026-11-25: IOU confirm codes are derived (HMAC-SHA256 of the creator's key over the IOU id, 8 bytes hex), so nothing is stored and a restored phone rebuilds reminder links. `IouTerms.confirmCodeHash` is omitted when null (`@EncodeDefault(NEVER)`) so M8 IOU hashes are unchanged. A web confirmation counts as the key-less party's signature but is documented as weaker than a co-signature; with a key-less party the creditor's own settlement settles.
- 2026-11-25: The IOU confirm link carries the terms field by field and both sides rebuild the canonical JSON (225 Base64url characters instead of 409 for the deflated JSON), keeping a reminder at three SMS parts; adding an `IouTerms` field requires a new link version, and the Playwright test with a core-signed fixture catches drift.
- 2026-11-25: QR codes hold at most 700 characters (about version 20 at EC M); longer events become `harkara:q:` multi-QR sets. Camera scanning is left to hardware (the phone's camera app opens `harkara:` links; in the app, paste works everywhere).
- 2026-11-25: A followed task (`t:` link) is subscribed to but shows in Tasks only if it is in the user's area or theirs; `g:` area links open the web page in the browser rather than changing the user's area.
- 2026-11-25: MapLibre Native Android is pinned to 13.7.1 (the newest stable that resolves with compileSdk 35, AGP 8.10, Kotlin 2.2). It reads PMTiles itself since 11.7 (`pmtiles://file://<path>`, documented for local files), so the app points the style at the installed pack instead of running a local HTTP tile server; glyphs load from `asset://glyphs/…`. The pure-Kotlin PMTiles reader in core still checks every pack before install and could back a local handler if `pmtiles://` ever fails on a phone (listed in HARDWARE.md).
- 2026-11-25: The M9 branch measured ~13 MB of MapLibre native code per ABI (arm64 release went from 19.7 MB to 33.5 MB). Native libraries are stored compressed (`jniLibs.useLegacyPackaging = true`, extracted at install); that branch measured arm64 at ~22 MB and armeabi-v7a at ~21 MB, at the cost of ~20 MB more space after install. The integrated APK still needs the per-ABI size gate; these are not new merged-build measurements.
- 2026-11-25: The map surface sits behind `MapSurface`; `MapLibreMapSurface` (one file) is the only code that touches MapLibre and is provided only by `MainActivity` through `LocalMapSurface`. Without a surface (tests, no pack, Lite) Map mode is the no-map Lite list, so JVM tests never load native code; screenshot tests use a `FakeMapSurface` with plain Web Mercator.
- 2026-11-25: Map markers (posts, pins, people, tasks, nodes, the user dot) are Compose overlays positioned through the surface's projection rather than MapLibre symbol layers: one rendering path for the phone and the tests, TalkBack labels and tap targets on every marker, and token colours without sprite sheets. `MapLayers` also gives the same markers as GeoJSON.
- 2026-11-25: Map labels follow the app language: Bangla (`name:bn`, then `name`, which Protomaps fills with Bangla for most of Dhaka) or English (`name:en`, then `name`). Glyphs bundled: Noto Sans Regular ranges 0-255, 2304-2559 (Bengali) and 8192-8447 from protomaps/basemaps-assets (OFL), ~240 KB; the fontstack is `NotoSans-Regular` so asset paths have no spaces.
- 2026-11-25: The "Places" layer is other people's shared and public pins; "My pins" are the user's own. The Nodes layer renders supplied M6 node markers; discovery and reachability belong to the carriers, and an empty marker list stays empty.
- 2026-11-25: Public pins are signed by the profile key (so the owner can edit or delete them as replaceable events), while "still there?" answers are signed by the weekly area key so answering stays anonymous like feed votes. A public pin's spot is its 9-character geohash `g` tag (±2.4 m) instead of a separate coordinate tag.
- 2026-11-25: Private pins are NIP-78 app data encrypted to the owner's own key and published like any event, so they come back after a key restore; the Saved pins module text says "encrypted to you" instead of "stay on this phone".
- 2026-11-25: Live share: the start is a stored gift wrap from the profile key that carries the session key plus the session key's signature binding it to the owner, share id and end; points are ephemeral wraps sealed by the session key with no timestamp tweak (they are delivered live anyway). Receivers keep `seq` and stops in memory; after an app restart a replayed point could only be accepted if an attacker captured an ephemeral wrap, which relays don't store.
- 2026-11-25: A user-started live share keeps running with the screen off through a foreground service of type `location` (`FOREGROUND_SERVICE_LOCATION`), with Stop in its notification; it asks for precise location (approximate is accepted) only when a share starts.
- 2026-11-25: Check-ins are private only (gift-wrapped to chosen people and to self), never public area events: a public "I'm here" signed by the profile key would tell everyone where a person is. The overdue alert is sent by the traveller's own phone at the deadline (one WorkManager job per active trip); watchers' phones pick it up in the app or in the existing 30-minute relay check (which now also subscribes to our gift wraps) and show a notification. Watcher-side alarms (a watcher's phone noticing the missing check-in itself, for when the traveller's phone is dead) are left for later.
- 2026-11-25: Pins, check-ins and live location share one `GiftInbox` that unwraps each gift wrap once and hands the rumor to the feature for its kind (Khata keeps its own path).
- 2026-11-25: The Offline map pack module stays off until a pack is installed: switching it on without a pack opens Map packs; a finished download or import switches it on, deleting the pack switches it off.
- 2026-11-25: The PMTiles test fixtures are written by `tools/pmtiles-fixture.py` with the reference Python implementation (`pip install pmtiles`, BSD-3-Clause) so the Kotlin reader is checked against an independent writer; they force leaf directories and a run-length entry.
