# Decisions

One line per decision: date, decision, why. Defaults from the handover (§11) are not repeated here.

- 2026-11-25: Seeded from a copy of `nearcast/` without git history; Nearcast's FastAPI `server/`, Vercel files and its product site were dropped. Harkara has no server (BDT 0/month) and gets a new site under `site/`.
- 2026-11-25: Design handover assets live in `design/` (`icons/`, `brand/`, `tokens/`, `copy/`), imported by `tools/import-handover.mjs`, which strips the embedded C2PA provenance blocks so SVGs can be inlined and converted.
- 2026-11-25: `Tokens.kt` and `site/assets/tokens.css` are generated by `tools/build-tokens.mjs`; vector drawables by `tools/icons-to-vectors.mjs`. CI runs both with `--check` so generated files never drift from `design/`.
- 2026-11-25: The launcher mark's dashed route is expanded into explicit dash segments in the vector drawable, because Android vectors have no `stroke-dasharray`.
- 2026-11-25: App settings use SharedPreferences behind `AppSettings` (a `StateFlow`), not DataStore — one fewer dependency and trivially testable under Robolectric.
- 2026-11-25: Screenshot goldens are Roborazzi images at 360 × 800 dp, mdpi (1:1 with the Figma renders), stored in `app/src/test/screenshots/`; CI verifies them with a 2% change threshold so font rasterising differences between Windows and Linux don't fail the build.
- 2026-11-25: Bangla UI uses Anek Bangla for all UI text styles (Compose has no per-glyph fallback between font families); Latin UI uses Geist with Anek Bangla only for explicit Bangla labels.
- 2026-11-25: R8 minification stays off until M12: BouncyCastle and reflection-heavy libraries are risky to shrink without on-device runs, and the APK is well under the 30 MB budget.
- 2026-11-25: The signing keystore is PKCS12, so the key password equals the store password (PKCS12 has one password); both secrets are still set.
- 2026-11-25: Nearcast's original design spec is kept as `docs/NEARCAST-SPEC.md` for history only; `HARKARA_HANDOVER.md` (outside the repo) and `AGENTS.md` are the rules now.
- 2026-11-25: Landing site templates are JS template-literal modules in `tools/site/` (render, icons, release, text helpers, inline JS sources, `site.css`). `tools/build-site.mjs` writes the pages, `site/assets/site.css` (minified from `tools/site/site.css`), `favicon.svg` and `latest.json` into `site/`; those outputs are git-ignored, so `site/` after a build is exactly the Pages artifact. Committed under `site/`: `config.json`, `.nojekyll`, `assets/tokens.css`, `assets/fonts/`.
- 2026-11-25: Icons are inlined as one per-page SVG sprite (`<symbol>` + `<use>`), holding only the icons that page uses; keeps each page well under the 120 KB budget.
- 2026-11-25: The local test server and Playwright serve `site/` under `/harkara/` (like GitHub Pages), so relative links, the `/` → `en/` redirect and the 404 page's `<base href="/harkara/">` are tested as deployed.
- 2026-11-25: Without a release the install step text drops its size (", {{APK_MB}} MB"), the footer drops "v{{VERSION}}", the SHA-256 box shows "—" with no Copy button, and the armeabi-v7a link opens the Releases page.
- 2026-11-25: `build-site.mjs` treats GitHub API 404 and network errors as "no release yet" (coming-soon page) but fails on other HTTP errors (rate limit, 5xx) so CI never deploys a downgraded page over a real release. If a release has no `latest.json` asset, one is rebuilt from the API asset list and `SHA256SUMS`.
- 2026-11-25: Privacy/verify and 404 pages need a few strings that `landing.json` doesn't have (Verify, certificate label, "published with the first release", not-found line); they live in `tools/site/strings.mjs` (bn + en).
- 2026-11-25: Mock card UIs on the landing keep the small English labels the Figma frames use in both languages ("Task · Pickup", "Khata · IOU", "Handoff code", "by SMS", "Public", "খাবার").
- 2026-11-25: The site's mono font is JetBrains Mono 500 only, Anek Bangla ships 500/600 (Bengali subset) and Geist 400/500/600 (Latin subset cut with fontTools); the Android TTFs for M2 come from the same families (see `site/assets/fonts/README.md`).
- 2026-11-25: secp256k1-kmp is pinned to 0.16.0, the newest release whose `-jni-jvm` runs on JDK 17 (0.17+ needs JDK 21 for the JVM tests). Its arm64 `libsecp256k1-jni.so` is not 16 KB page aligned (lint warning); move to the latest release when CI moves to JDK 21.
- 2026-11-25: XChaCha20-Poly1305 for NIP-49 is HChaCha20 (own code, checked against the draft-irtf-cfrg-xchacha vector) in front of BouncyCastle's RFC 8439 ChaCha20-Poly1305; BouncyCastle 1.78 has no XChaCha. NIP-44 uses BouncyCastle's ChaCha7539Engine and JCA HMAC/SHA-256.
- 2026-11-25: NIP-01 serialization escapes other control characters and lone surrogates as lowercase `\u00xx`, exactly like `JSON.stringify`, so ids agree with nostr-tools for every string.
- 2026-11-25: Harkara app kinds: 3471 task step, 3472 handoff token, 3473 IOU, 3474 IOU signature, 3475 settle, 3476 check-in, 3477 SOS, 3478 SOS update, 23471 live location, 33471 pin. No NIP uses this block. Area chat uses kind 20000 (bitchat's geohash-channel convention).
- 2026-11-25: Key ring = HKDF-SHA256 with an empty salt over the 32-byte seed and labels `harkara/v1/{profile,area/<g5>/<week>,mesh/<date>,session/<id>}`; an invalid scalar retries with `#1`, `#2`… appended to the label. ISO weeks and mesh days turn over on Asia/Dhaka time.
- 2026-11-25: The NIP-49 backup holds the 32-byte root seed in the "private key" field (log_n 16, key-security byte 0x02), not the profile key, so one backup restores every derived key. Backup passwords need at least 8 characters.
- 2026-11-25: The seed file lives at `noBackupFilesDir/identity/root-seed` (inside what panic wipe empties), sealed with an AndroidKeyStore AES-256-GCM key when the provider exists and plain otherwise (Robolectric). If a sealed seed can no longer be opened (keystore reset) the app makes a new identity; restoring a backup brings the old one back.
- 2026-11-25: Keys are made when onboarding completes (an area is chosen), not at install, so "Restore from backup" on the onboarding screen never has to replace a key the user already used.
- 2026-11-25: Peer rate limits count sliding windows over `created_at` (order-independent), only for kind 1 posts; events more than 15 minutes in the future are dropped so the windows cannot be dodged by future-dating.
- 2026-11-25: The mesh dedupe marks an id seen only after the event verifies, so a forged copy with a real id cannot block the real event. Fragments are link-local: every hop reassembles and verifies before relaying.
- 2026-11-25: NIP-13 `meets(event, bits)` requires a committed target in the nonce tag that is at least `bits` (the NIP allows rejecting uncommitted PoW).
- 2026-11-25: The binary codec deflates content only when that is smaller and has an "id omitted" flag for SMS (the decoder recomputes the id); created_at is u32, so events after 2106 cannot be carried in binary.
- 2026-11-25: Nearcast leftovers without an event equivalent yet were removed rather than half-ported: CryptoBox/NearId/AES-GCM DMs, PacketCodec, ReactionCounter, AckStateMachine, ChannelMessage/ChannelFilter, FeedOrdering/PostKind. Votes return as kind 7 (M4), delivery states and channels as events (M5). SosPolicy and RetentionPolicy now work on events.
- 2026-11-25: The backup QR is always drawn with Day ink on Day surface, also in the Night theme, because many scanners cannot read inverted codes.
- 2026-11-25: SQLCipher is pinned to 
et.zetetic:sqlcipher-android 4.10.0: 4.20.0 requires compileSdk 36 and the handover fixes compileSdk 35. The 32-byte database key is random, kept in no-backup storage and erased by panic wipe; JVM tests use a plain in-memory Room database (HarkaraDatabase.inMemory).
- 2026-11-25: The app's relay pool lives in pp/relay (OkHttp), while the NIP-01 message codec, NIP-11 parsing, backoff, NIP-77 negentropy and the I/O-free LocalRelay live in core/relay so the LAN room and node can reuse them.
- 2026-11-25: Negentropy (NIP-77) is our own Kotlin implementation of protocol v1, written from the published description; it is used for the area-feed catch-up only on relays whose NIP-11 lists 77.
- 2026-11-25: Feed posts carry g tags at precisions 7, 6 and 5; the app subscribes to the area's geohash-5 cell and its eight neighbours and keeps posts within 3 km of the area centre. Peers require NIP-13 ≥ 16 bits; the composer tunes 16–20 bits to about 2 s of mining on the phone.
- 2026-11-25: Relays connect only while an activity is visible or during the 30-minute WorkManager sync (network + battery-not-low constraints), per the battery rule.
- 2026-11-25: The map style builder (core/map/MapStyle) labels with 
ame:bn first, falling back to 
ame; MapLibre's support for Bangla glyph shaping is listed in HARDWARE.md as unverified.
- 2026-11-25: The emergency handbook (data/handbook, 42 sections, en + bn, ~365 KB) ships inside the APK because the Handbook module is on by default and must work with no network; only further translations would be downloads. Handbook pages use the polite আপনি form (public-safety convention); app UI strings use তুমি.
- 2026-11-25: Task steps are replayed in time order with lifecycle order breaking ties, and steps that aren't valid yet are retried until nothing changes, so a countersign made in the same second as the accept (or from a phone whose clock is behind) still counts.
- 2026-11-25: The 6-digit handoff code is derived from the requester's signed token; the requester commits to scrypt(code, task address + runner, N=2^14) in the countersign step, so the runner's phone checks a typed code offline while trying all million codes stays impractically slow. The token itself never leaves the requester's phone except as the QR (kept in the local_secrets table, never sent by any carrier).
- 2026-11-25: Display names travel as a 
ame tag on task offers and accepts (and later IOUs) so they show on phones that never saw a kind-0 profile; names are free text without digits in the UI.
- 2026-11-25: Reputation uses NIP-51-style verified-contact lists (owner → keys verified in person); until verified contacts exist, only tasks the viewer took part in count.
- 2026-11-25: SMS payload format v1 (`HK1:` + Base64url, `core/wire/SmsCodec`): 8-byte author reference, u32 time, 64-byte signature, compact tag items (hex/UUID/decimal/joined address/back-references), text as Text8 (one byte per Bangla letter) DEFLATEd with a fixed preset dictionary. 32-byte values the receiver already knows become 8-byte references only when the full form doesn't fit two SMS, so gateways and strangers can still verify most SMS.
- 2026-11-25: Short DMs on the SMS rung are a new app kind 3479 (NIP-44 v2 to one `p`, signed by the sender) instead of a NIP-59 gift wrap, which cannot fit two SMS; the SMS carrier sees both numbers anyway. Plaintext is limited to 32 UTF-8 bytes (one NIP-44 padding block).
- 2026-11-25: SMS field limits (`SmsLimits`): check-in place 40 + note 40 characters, SOS note 60, task name 40, TrxID 20, DM 32 bytes; every SMS-eligible kind at those limits fits two GSM-7 parts (`SmsBudgetTest`).
- 2026-11-25: `SEND_SMS` and `RECEIVE_SMS` are declared in the one manifest (Android can only ask for declared permissions) but requested only when the user turns on "Send SMS directly" or "Volunteer SMS gateway"; both SMS receivers ship as disabled components and are enabled/disabled with their switch. No separate no-SMS build flavor for now (one APK set, Obtainium naming); revisit if a store or Play Protect objects.
- 2026-11-25: When Android refuses the SMS permission (e.g. Android 13+ restricted settings for sideloaded APKs) the app shows a guidance screen (App info → ⋮ → Allow restricted settings → Permissions → SMS) instead of detecting the restriction, which has no public API.
- 2026-11-25: The volunteer gateway relays only while relays run (app open or the 30-minute background sync), with no always-on service (battery rule); its 100/day cap counts SMS in and out per Dhaka day, and events are deduplicated by id. The volunteer's own number lives only in their gateway QR (`harkara:gw:`).
- 2026-11-25: Data SMS for "Send SMS directly" use port 7471 and a 3-byte frame header (133-byte frames, any order); every SMS-eligible event fits two frames.
- 2026-11-25: The https deep link (`tanzir71.github.io/harkara/o/`) is declared without `autoVerify`: assetlinks.json would have to be served from the root of tanzir71.github.io, which this project does not control. The o/ page offers an "Open in Harkara" (`harkara:`) button instead.
- 2026-11-25: The web page for non-users bundles @noble/curves + @noble/hashes (MIT) with esbuild (MIT, devDependency) into `site/assets/o.js` (~50 KB) with its own budget (JS 60 KB, CSS 48 KB, page 160 KB); a CSP meta pins WebSockets to `data/default-relays.json` and forbids inline scripts. Compressed `e:` content is inflated with the browser's `DecompressionStream('deflate-raw')` (Chrome 103+, Safari 16.4+, Firefox 113+) rather than bundling an inflater.
- 2026-11-25: IOU confirm codes are derived (HMAC-SHA256 of the creator's key over the IOU id, 8 bytes hex), so nothing is stored and a restored phone rebuilds reminder links. `IouTerms.confirmCodeHash` is omitted when null (`@EncodeDefault(NEVER)`) so M8 IOU hashes are unchanged. A web confirmation counts as the key-less party's signature but is documented as weaker than a co-signature; with a key-less party the creditor's own settlement settles.
- 2026-11-25: The IOU confirm link carries the terms field by field and both sides rebuild the canonical JSON (225 Base64url characters instead of 409 for the deflated JSON), keeping a reminder at three SMS parts; adding an `IouTerms` field requires a new link version, and the Playwright test with a core-signed fixture catches drift.
- 2026-11-25: QR codes hold at most 700 characters (about version 20 at EC M); longer events become `harkara:q:` multi-QR sets. Camera scanning is left to hardware (the phone's camera app opens `harkara:` links; in the app, paste works everywhere).
- 2026-11-25: A followed task (`t:` link) is subscribed to but shows in Tasks only if it is in the user's area or theirs; `g:` area links open the web page in the browser rather than changing the user's area.
